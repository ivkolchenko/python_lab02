## Форматы входных данных

Каждое событие содержит четыре обязательных поля:

| Поле | Описание |
| --- | --- |
| `timestamp` | Дата и время ISO 8601 с часовым поясом, например `2024-06-01T12:00:00+00:00` или `2024-06-01T12:00:00Z` |
| `level` | Одно из значений `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `source` | Непустая строка с названием источника |
| `message` | Строка с текстом события |

CSV-файл начинается с заголовка:

```csv
timestamp,level,source,message
2024-06-01T12:00:00+00:00,INFO,api,Started
2024-06-01T12:30:00+00:00,ERROR,db,Connection lost
```

В JSONL каждая строка содержит отдельный JSON-объект:

```jsonl
{"timestamp":"2024-06-01T12:00:00+00:00","level":"INFO","source":"api","message":"Started"}
{"timestamp":"2024-06-01T12:30:00+00:00","level":"ERROR","source":"db","message":"Connection lost"}
```

Примеры входных файлов находятся в [`tests/fixtures`](tests/fixtures)

## Возможности программы

1. Чтение CSV с заголовком и JSONL по строкам без загрузки всего входного файла в память
2. Проверка временной метки, уровня и обязательных полей события
3. Подсчёт общего числа принятых событий и событий каждого уровня и источника
4. Отдельный top-5 источников для уровней `ERROR` и `CRITICAL`
5. Поиск самой ранней и самой поздней временных меток
6. Подсчёт пропущенных записей в режиме `--skip-invalid`
7. Создание JSON-отчёта в указанном файле

## Как работает анализ

1. Команда `analyze` выбирает парсер по значению `--format` и создаёт объект `LogStatistics`.
2. Парсер перебирает записи CSV или строки JSONL. Для каждой записи он разбирает `timestamp` и создаёт `EventModel`
3. Функция `analise()` обновляет счётчики уровней и источников, счётчики ошибок и границы времени
4. Функция `json_report()` преобразует статистику в словарь и записывает JSON-отчёт

Модель `EventModel` описана в `models.py`. Статистика накапливается в `LogStatistics` с помощью `collections.Counter`. Время сравнивается с учётом часового пояса

Если файл отчёта уже существует и содержит JSON-объект или массив, новая статистика добавляется в массив. Повторный запуск команды создаёт ещё одну запись отчёта, а не объединяет результаты запусков

## Запуск программы

Команды ниже выполняются из корня репозитория. Текущий код импортирует модули как `src.streamstats`, поэтому для запуска из исходников используется эта форма:

```bash
python -m streamstats analyze INPUT --format csv|jsonl --output REPORT.json [--skip-invalid]
```

Справка:

```bash
python -m streamstats --help
```

Параметры `--format` и `--output` обязательны. Команда принимает один входной файл

## Обработка ошибок

В `errors.py` определён базовый `StreamstatsError` и отдельные типы ошибок: `UnsupportedFormat`, `InvalidEvent`, `InvalidTimestamp`, `CliConfigurationError`

Без `--skip-invalid` неверная временная метка или событие останавливает обработку. Ошибки `StreamstatsError` выводятся в `stderr`, а CLI завершается с кодом `2`. С параметром `--skip-invalid` часть неверных записей пропускается, выводится предупреждение и увеличивается `skipped_count`

Отсутствующий входной файл, пустой файл, неверная кодировка UTF-8, отсутствующий столбец CSV и повреждённый JSONL обрабатываются как ошибки конфигурации или формата. Для повреждённого JSONL параметр `--skip-invalid` сейчас не позволяет продолжить чтение
